# Jastip — Aplikasi Jasa Titip (Flutter + Firebase)

Aplikasi marketplace jasa titip sederhana. Setiap user bisa berperan ganda
sebagai **requester** (yang nitip) maupun **traveler** (yang membantu beli).

## 2. Firestore Collection Design

```
users/{uid}
  - name: string
  - email: string
  - phone: string?
  - photoUrl: string?
  - createdAt: timestamp

requests/{requestId}
  - requesterId: string  (uid)
  - requesterName: string
  - itemName: string
  - location: string
  - estimatedPrice: number
  - initialFee: number
  - currentFee: number              # bisa berubah saat negosiasi
  - note: string?
  - imageUrl: string?
  - status: string                  # OPEN | NEGOTIATION | WAITING_CONFIRMATION
                                    # | ACCEPTED | PURCHASED | COMPLETED
  - travelerId: string?
  - travelerName: string?
  - proofImageUrl: string?
  - receiptImageUrl: string?
  - createdAt: timestamp
  - updatedAt: timestamp

  └── messages/{messageId}          # subcollection chat
        - senderId: string
        - senderName: string
        - text: string
        - createdAt: timestamp
```

### Status Flow

```
OPEN ──(traveler take)──► NEGOTIATION
NEGOTIATION ◄──(requester reject)──┐
NEGOTIATION ──(propose fee)──► NEGOTIATION (loop)
NEGOTIATION ──(requester accept)──► WAITING_CONFIRMATION
WAITING_CONFIRMATION ──(requester confirm)──► ACCEPTED
ACCEPTED ──(traveler upload proof)──► PURCHASED
PURCHASED ──(requester complete)──► COMPLETED
```

## 3. Firebase Setup

```bash
# 1. Install FlutterFire CLI
dart pub global activate flutterfire_cli

# 2. Buat Firebase project di console.firebase.google.com
#    Aktifkan: Authentication (Email/Password), Firestore, Storage

# 3. Generate firebase_options.dart
flutterfire configure

# 4. Deploy rules
firebase deploy --only firestore:rules,storage
```

`firestore.rules` dan `storage.rules` sudah disiapkan di root project.

## 4. State Management

Menggunakan **Provider** (`ChangeNotifier`):

- `AuthProvider` — listen `authStateChanges`, expose login/register/logout
- `RequestProvider` — bungkus `RequestService`, expose stream + action

Dipasang di `app.dart` via `MultiProvider`. Halaman-halaman pakai
`context.watch<T>()` untuk rebuild otomatis.

## 5. Routing

Sederhana via `Navigator.push(MaterialPageRoute(...))`. Routing utama
dijaga oleh `_AuthGate` di `app.dart`:

- `unknown` → loading
- `unauthenticated` → `LoginScreen`
- `authenticated` → `HomeScreen` (bottom navigation)

## 6. Contoh Query Firestore

```dart
// Stream semua request OPEN (Home)
FirebaseFirestore.instance
  .collection('requests')
  .where('status', isEqualTo: 'OPEN')
  .orderBy('createdAt', descending: true)
  .snapshots();

// Request milik user (sebagai requester)
.collection('requests')
  .where('requesterId', isEqualTo: uid)
  .orderBy('createdAt', descending: true)
  .snapshots();

// Request yang user ambil (sebagai traveler)
.collection('requests')
  .where('travelerId', isEqualTo: uid)
  .orderBy('updatedAt', descending: true)
  .snapshots();
```

> **Catatan**: query yang menggabungkan `where` + `orderBy` pada field
> berbeda perlu **composite index**. Jalankan app, error log akan memberi
> link otomatis ke Firebase Console untuk membuat index.

## 7. Contoh CRUD

```dart
// CREATE
await FirebaseFirestore.instance
    .collection('requests')
    .add(request.toMap());

// UPDATE (negosiasi fee)
await FirebaseFirestore.instance
    .collection('requests')
    .doc(id)
    .update({
  'currentFee': newFee,
  'status': 'NEGOTIATION',
  'updatedAt': Timestamp.now(),
});

// DELETE
await FirebaseFirestore.instance
    .collection('requests')
    .doc(id)
    .delete();
```

## 9. Menjalankan

```bash
flutter pub get
flutterfire configure   # generate firebase_options.dart
flutter run
```

## 10. Best Practice

- Pisahkan layer: **model → service → provider → screen**
- Gunakan `StreamBuilder` untuk data realtime
- `Timestamp.now()` di server-side (kalau perlu konsistensi, ganti ke `FieldValue.serverTimestamp()`)
- Validasi form sebelum hit Firestore
- Firestore rules di-set ketat (lihat `firestore.rules`)
- File terstruktur per fitur (feature-first folder)
